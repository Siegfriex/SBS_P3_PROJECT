인지했습니다. 당신이 설계하는 것은 일반적인 의미의 “회의록 텍스트 정제”가 아니라, **병렬 브랜치가 선정한 이슈를 기준으로 원본 회의록에서 관련 질의·답변 구간을 회수하는 검색형 전처리 파이프라인**입니다.

회의에서 말한 “마킹된 주제를 정답처럼 사용해 전체 회의록에서 관련 부분만 남긴다”는 구조를 기술적으로 구체화하면 다음과 같습니다. 

## 1. 전체 구조

```text
[병렬 브랜치]
처리결과보고서 검토
→ 주요 주제·논제·사건 마킹
→ 주제별 기준 텍스트 생성
→ topic seed dataset

[우리 브랜치]
회의록 PDF 전체 파싱
→ 발언·문장·구간 단위 분절
→ TF-IDF 수치화
→ topic seed와 유사도 계산
→ 임계값 기반 관련 구간 선별
→ 앞뒤 맥락 및 질의·답변 복원
→ 관계형 인덱스 생성

[후속 단계]
임베딩 모델
→ 의미 기반 재순위화
→ LLM 기반 질의·답변 구조화
→ 처리결과·뉴스 데이터와 연결
```

핵심은 TF-IDF가 최종 분석 모델이 아니라 **고재현율 후보 추출기**, 즉 1차 lexical filter 역할을 하는 것입니다.

## 2. 정확한 학습 개념

병렬 브랜치에서 제공하는 텍스트만으로 TF-IDF 유사도를 계산한다면, 엄밀하게는 완전한 지도학습이라기보다 다음에 가깝습니다.

> 주제별 seed text를 이용한 약지도 학습 또는 prototype-based retrieval

예를 들어 병렬 브랜치가 다음 텍스트를 제공합니다.

```text
topic_id: T024
주제: 국악 공연 관련 특혜 의혹
핵심 논제: 특정 인물과 관련된 국악 공연 추진 과정 및 예산 집행의 적절성
마킹 원문: ...
핵심어: 국악, 공연, 예산, 특혜, 대통령실, 문체부
관련 기관: 문화체육관광부, 국립국악원
```

이것을 벡터화한 뒤, 회의록의 각 발언 구간과 cosine similarity를 계산하는 구조입니다.

```text
similarity(segment, topic)
    = cosine(TFIDF(segment), TFIDF(topic_seed))
```

다만 한 주제에 여러 개의 마킹 문장이 있다면, 모두 하나의 긴 텍스트로 합치는 것보다 개별 seed로 유지하는 것이 좋습니다.

```text
topic T024
 ├─ seed_01: 처리결과보고서 제목
 ├─ seed_02: 지적사항 원문
 ├─ seed_03: 처리결과 요약문
 ├─ seed_04: 수작업 논제 설명
 └─ seed_05: 핵심 키워드 확장문
```

점수는 다음 중 하나로 계산할 수 있습니다.

```text
최대 점수 방식
score = max(cosine(segment, seed_j))

평균 prototype 방식
score = cosine(segment, mean(seed_vectors))

혼합 방식
score = 0.7 × max_score + 0.3 × centroid_score
```

초기에는 혼합 방식이 적절합니다. 평균 벡터만 사용하면 서로 다른 표현이 희석될 수 있고, 최대값만 사용하면 우연한 단어 일치에 민감해질 수 있습니다.

## 3. 가장 중요한 단위 설정

PDF 전체를 하나의 문서로 TF-IDF화하면 안 됩니다. 그렇게 하면 특정 이슈가 포함되어 있어도 전체 문서의 수십만 단어에 희석됩니다.

처리 단위는 다음 계층으로 나눠야 합니다.

| 단위            | 역할                 |
| ------------- | ------------------ |
| PDF           | 회의 전체 메타데이터        |
| 페이지           | 원문 위치 복원           |
| 발언 turn       | 한 발언자의 연속 발언       |
| 검색 segment    | TF-IDF 유사도 계산 단위   |
| Q&A exchange  | 질의·답변 맥락 단위        |
| issue episode | 특정 주제를 다룬 전체 대화 구간 |

### 권장 TF-IDF 검색 단위

기본 단위는 `speaker turn`만으로는 부족할 수 있습니다. 짧은 답변은 정보가 너무 적고, 긴 의원 발언은 여러 주제가 혼재할 수 있기 때문입니다.

따라서 두 가지 단위를 함께 만드는 것이 좋습니다.

```text
A. 발언 단위
한 명의 연속 발언

B. 슬라이딩 문맥 단위
현재 발언 + 이전 1개 발언 + 이후 1개 발언
```

또는 토큰 기준으로 다음과 같이 구성할 수 있습니다.

```text
segment length: 250~600자
overlap: 80~150자
발언자 경계는 가급적 유지
```

중요한 것은 모든 segment가 원본 위치를 되찾을 수 있어야 한다는 점입니다.

```text
segment_id
meeting_id
page_start
page_end
turn_start_id
turn_end_id
char_start
char_end
```

## 4. TF-IDF 파이프라인

### 4.1 공통 코퍼스 생성

TF-IDF vocabulary는 다음을 함께 넣어 생성해야 합니다.

```text
전체 회의록 segment
+
병렬 브랜치 topic seed
```

그래야 동일한 feature space에서 cosine similarity를 계산할 수 있습니다.

```text
corpus = raw_segments + topic_seeds
vectorizer.fit(corpus)
```

다만 TF-IDF의 IDF가 seed 문장에 의해 과도하게 바뀌지 않도록, seed가 전체 문서 수에 비해 적다는 전제에서 진행하면 됩니다.

### 4.2 한국어 TF-IDF 권장 구성

한국어 회의록은 띄어쓰기 오류, 기관명 복합어, 이름과 직책 결합이 많으므로 한 종류의 TF-IDF만 사용하면 취약합니다.

두 채널을 병렬로 쓰는 것이 적합합니다.

#### 단어 기반 TF-IDF

```text
tokenizer: Kiwi 또는 Mecab
ngram_range: (1, 2)
sublinear_tf: True
min_df: 2
max_df: 0.95
norm: l2
```

명사만 남기는 방식은 권하지 않습니다. `아니다`, `모른다`, `검토하겠다`, `제출하겠다` 같은 응답 동사가 중요하기 때문입니다.

#### 문자 기반 TF-IDF

```text
analyzer: char_wb
ngram_range: (2, 5) 또는 (3, 5)
min_df: 2
sublinear_tf: True
```

문자 n-gram은 띄어쓰기 오류와 OCR 오류, 복합 기관명에 강합니다.

최종 lexical score는 예를 들어 다음과 같이 합칠 수 있습니다.

```text
tfidf_score
    = 0.6 × word_tfidf_cosine
    + 0.4 × char_tfidf_cosine
```

이 가중치는 파일럿에서 조정합니다.

## 5. 임계값 처리 방식

당신이 말한 “임계값 이하 텍스트를 날린다”는 것은 파이프라인 논리상 맞습니다. 다만 원본 데이터를 실제로 삭제하면 안 됩니다.

데이터를 다음 세 층으로 분리해야 합니다.

```text
Raw layer
모든 PDF와 전체 파싱 원문 영구 보존

Candidate layer
TF-IDF 임계값을 통과한 후보만 저장

Verified layer
임베딩·사람 검수 등을 거쳐 최종 관련 구간으로 확정
```

즉, “날린다”는 것은 다음 의미여야 합니다.

> 이후 분석 대상에서 제외하지만 원본 저장소에서는 보존한다.

임계값도 하나의 전역 임계값만 쓰는 것보다 주제별 임계값을 쓰는 것이 적절합니다. 어떤 주제는 고유명사가 명확하고, 어떤 주제는 `예산`, `운영`, `개선`처럼 일반어가 많기 때문입니다.

### 3단계 판정 방식

```text
score >= τ_keep
→ 자동 후보 채택

τ_review <= score < τ_keep
→ 경계 후보, 임베딩 또는 수작업 검토

score < τ_review
→ 분석 후보군에서 제외
```

예시입니다.

```text
score >= 0.30       자동 유지
0.18 <= score < 0.30 검토
score < 0.18        후보 제외
```

이 숫자는 예시일 뿐이며 실제 문서로 검증해야 합니다.

### 임계값 실험

각 주제별로 다음 표본을 확인합니다.

```text
Top 20
Top 21~50
임계값 근처 30개
낮은 점수 무작위 20개
```

그리고 다음을 측정합니다.

```text
Precision@10
Precision@20
Recall 추정치
False positive 유형
False negative 유형
```

초기 1차 필터는 정밀도보다 재현율을 우선해야 합니다. 관련 발언을 놓치면 이후 임베딩이나 LLM이 복구할 수 없기 때문입니다.

## 6. TF-IDF 이후 맥락 복원

TF-IDF가 반환하는 것은 관련성이 높은 `anchor segment`입니다. 이 segment 자체가 최종 결과는 아닙니다.

예를 들어 다음 문장이 높은 점수를 받았다고 가정합니다.

```text
○홍길동 위원
해당 공연 예산이 어떤 절차로 승인됐습니까?
```

최종 산출물에는 다음이 모두 필요합니다.

```text
이전 컨텍스트
→ 해당 질문이 나오게 된 배경

질의 원문
→ 의원 질문 전체

답변 원문
→ 장관·기관장·실무자 답변 전체

재질의
→ 답변 이후 의원의 반박 또는 추가 질문

이후 컨텍스트
→ 자료 제출 약속, 시정 요구, 주제 종료
```

따라서 TF-IDF 후보를 찾으면 원본 turn 인덱스를 기준으로 확장합니다.

```text
anchor segment 발견
→ anchor가 속한 speaker_turn 확인
→ 앞의 의원 질의 시작점 탐색
→ 뒤의 답변자 발언 연결
→ 같은 의원의 재질의까지 연결
→ 다음 의원의 새로운 질의 시작 전 종료
```

### Q&A exchange 기본 규칙

```text
START
의원 또는 위원의 실질적 질의 시작

CONTINUE
장관·차관·기관장·실무자의 답변
같은 의원의 재질의
보충답변
위원장의 짧은 중재

END
다른 의원의 새로운 질의 시작
의사일정 전환
감사 중지·종료
```

단순히 `앞뒤 3문장`만 붙이는 것보다 발언자 역할을 이용한 exchange 복원이 정확합니다.

## 10. 임베딩 단계의 위치

전체 순서는 다음처럼 두는 것이 가장 합리적입니다.

```text
1. PDF 파싱
2. turn·segment 구성
3. TF-IDF 후보 검색
4. 낮은 관련도 후보 제외
5. 임베딩 기반 의미 유사도 재평가
6. Q&A exchange 복원
7. LLM 기반 구조화·분류
8. 처리결과 및 기사 데이터와 연결
```

OpenAI 임베딩은 모든 원문에 바로 적용할 수도 있지만, 현재 목적에서는 TF-IDF로 먼저 후보군을 줄인 뒤 적용하는 것이 비용과 검증 측면에서 유리합니다.

다만 주제 표현과 실제 회의 발언의 어휘 차이가 클 수 있으므로 TF-IDF 필터를 지나치게 강하게 잡으면 안 됩니다.

예를 들어 처리결과보고서에는 다음과 같이 요약될 수 있습니다.

```text
국악 공연 추진 과정의 적절성 검토
```

실제 회의록에는 다음처럼 등장할 수 있습니다.

```text
누가 지시했습니까?
대통령실에서 연락받은 사실이 있습니까?
특정인을 위한 행사였습니까?
```

이 경우 정확한 단어가 겹치지 않아 TF-IDF 점수가 낮을 수 있습니다. 따라서 초기에는 넓게 회수하고, 임베딩에서 의미적으로 줄이는 구조가 적합합니다.

## 11. 현재 설계의 정확한 명칭

당신이 구상한 1차 시스템은 다음처럼 정의할 수 있습니다.

> 마킹된 감사 이슈를 약지도 seed로 사용하여 국정감사 회의록 전체를 TF-IDF 기반으로 검색하고, 관련 후보 구간을 선별한 뒤 원본 발언 인덱스를 통해 질의·답변 및 전후 문맥을 복원하는 이슈 중심 회의록 검색·구조화 파이프라인

개념적으로는 정확합니다. 다만 세 가지 원칙은 고정해야 합니다.

1. TF-IDF 단위는 PDF가 아니라 발언 또는 문맥 segment입니다.
2. 임계값 이하 데이터는 원본에서 삭제하지 않고 후보 분석층에서만 제외합니다.
3. TF-IDF가 찾은 문장은 최종 결과가 아니라 Q&A exchange를 복원하기 위한 anchor입니다.

이 세 가지를 지키면 이후 임베딩, 응답 패턴 분류, 처리 상태 매핑까지 구조적으로 연결됩니다.
